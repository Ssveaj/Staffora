# ADR 0022: Data model conventions

## Status

Accepted

## Context

Every entity needs the same audit columns, tenant indexing, relationship behaviour and type conventions. Conventions that depend on each developer remembering them are applied inconsistently.

## Decision

- Every tenant row implements `ITenantEntity` and is configured through one shared method that adds a `TenantId` index, `CreatedBy`, `ModifiedBy` and `ImpersonatedBy` foreign keys with `NoAction`, and the audit columns `Created`, `CreatedById`, `Modified`, `ModifiedById` and `ImpersonatedById`.
- The audit columns are stamped in `SaveChanges` from the runtime and the injected `TimeProvider`: the effective user while impersonating, and the target tenant's system account for cross-tenant writes.
- Model conventions hold for the whole model:
  - `DateTime` reads back as UTC;
  - every persisted enum declares explicit values that are never renumbered;
  - every string has a maximum length;
  - every relationship is `NoAction` unless the child is an owned row without a lifecycle;
  - ids are `Guid`s generated by EF, never assigned by hand.
- The context is built from one shared options method used by the application, the design-time factory and the tests.
- Migrations were reset to a single `InitialCreate` while the model was being rewritten, and are additive only after the first shared deployment.

## Rationale

Stating these conventions once and enforcing them with model tests means every entity gets them without anyone having to remember them.

## Consequences

- A model test fails on a relationship that cascades without being listed as owned, a tenant row without a `TenantId` index, a string without a maximum length, an enum without explicit values, or a `DateTime` that reads back with another kind.
- `dotnet ef` works through the design-time factory without building the web project.
- `Modified` and `ModifiedById` record the last writer of a row; the workflow history records transitions. Field-level change history is not kept.
- Seeding runs on a system context inside a system-scope lease, with production data (the `Admin` role, nothing with credentials) separate from Development data. Outside Development, the platform tenant and its first owner come from the one-time bootstrap command (`bootstrap-platform-owner`, [ADR 0012](0012-platform-owner-and-tenant-onboarding.md)).
- While migrations are still reset, a schema change regenerates `InitialCreate`, and development and end-to-end databases are recreated.
